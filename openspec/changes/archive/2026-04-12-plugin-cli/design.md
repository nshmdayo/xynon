## Context

`xynon` は現在プロキシ起動専用の単一コマンドである。プラグインのライフサイクル（追加・削除・一覧・ビルド）を操作する手段がなく、ユーザーはファイルシステムと設定 YAML を直接操作する必要がある。今回は `xynon plugin <subcommand>` 形式のサブコマンド群を標準ライブラリ (`flag` パッケージ) だけで実装し、外部 CLI フレームワークへの依存を追加しない。

既存の `internal/config` パッケージは読み取り専用であるため、設定ファイルへの書き戻しをサポートするための拡張が必要である。また、TinyGo ビルドは `os/exec` 経由の外部プロセス呼び出しとして実装する。

## Goals / Non-Goals

**Goals:**
- `xynon plugin list` でプラグインの状態を一覧表示できる。
- `xynon plugin add <path>` でプラグインをディレクトリにコピーし設定に追加できる。
- `xynon plugin remove <name>` で設定からプラグインを除外できる。
- `xynon plugin build <src-dir>` で TinyGo を使って WASM をビルドできる。
- 既存の `xynon -config` によるプロキシ起動の動作を変えない。
- 新規外部ライブラリ依存を追加しない。

**Non-Goals:**
- プラグインのバージョン管理やリモートレジストリからのインストール。
- WASM ファイル自体の削除（`remove` はチェーンから除外するだけ）。
- 対話的な UI や補完機能。
- Windows 対応（TinyGo の呼び出し方法が異なるため今回のスコープ外）。

## Decisions

### Decision 1: サブコマンドは標準 `flag` パッケージで実装する

- **選択**: `os.Args[1]` でトップレベルコマンドを判定し、`os.Args[2]` でサブコマンドを判定する。各サブコマンドは独立した `flag.FlagSet` を持つ。
- **理由**: 外部フレームワーク（cobra など）を追加せず、標準ライブラリのみに留める。サブコマンドは 4 つと少数で、`flag` の階層的な利用で十分。
- **代替案**: cobra / urfave/cli → 依存追加を避けるために却下。

### Decision 2: サブコマンドロジックは `internal/plugincli` パッケージに分離する

- **選択**: `cmd/xynon/main.go` はディスパッチのみ担い、各サブコマンドの実装は `internal/plugincli/` に置く。
- **理由**: `main.go` の肥大化を防ぎ、ロジックのユニットテストを容易にする。

### Decision 3: 設定ファイルの書き戻しは YAML ライブラリで行う

- **選択**: `gopkg.in/yaml.v3` を使い、現在の Config 構造体を再シリアライズして元のパスに書き戻す。コメントは保持されない。
- **理由**: 既に yaml.v3 が依存に入っており、新しいライブラリを追加しない方針に合致する。コメントの保持は今回の優先事項ではない。
- **代替案**: `yaml.Node` による構造保持 → 実装複雑度が高く、今回のスコープでは過剰。

### Decision 4: `plugin build` は TinyGo を外部プロセスで呼び出す

- **選択**: `os/exec` で `tinygo build -target wasip1 -o <out> <src>` を実行する。TinyGo のパスは `PATH` から解決するほか、環境変数 `TINYGO` で上書き可能にする。GOROOT の問題（Go 1.26 非対応）は、環境変数 `XYNON_TINYGO_GOROOT` を通じてユーザーが指定できるようにする。
- **理由**: TinyGo は go ビルドに含められないため外部コマンドが必然。環境変数でのオーバーライドは既存の Makefile との互換性を保ちつつ、スクリプトからも使いやすい。

### Decision 5: `plugin add` でのファイルコピーは上書きを許可する

- **選択**: 同名の `.wasm` がプラグインディレクトリに既にある場合は上書きし、設定のチェーンに二重追加しない（既存エントリを維持）。
- **理由**: ユーザーが同一名プラグインを更新する場合に余計な手順が発生しない。

## Risks / Trade-offs

- **[リスク] 設定ファイル書き戻し時にコメントが失われる** → ドキュメントで明示する。コメントの保持が必要になった場合は `yaml.Node` ベースの実装に切り替える。
- **[リスク] TinyGo が PATH に存在しない環境でビルドが失敗する** → `plugin build` 実行時に `tinygo` が見つからない場合は明確なエラーメッセージとインストール手順を表示する。
- **[トレードオフ] `plugin remove` は WASM ファイルを削除しない** → 誤削除を防ぐ安全側の設計。不要ファイルが残るが、運用者が手動で削除できる。
