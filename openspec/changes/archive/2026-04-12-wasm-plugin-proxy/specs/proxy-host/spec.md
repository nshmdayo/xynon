## ADDED Requirements

### Requirement: HTTP フォワードプロキシのリスン

プロキシホストは設定ファイルで指定されたアドレスで HTTP フォワードプロキシとしてリクエストを受け付け、標準 Go の `net/http` を用いて upstream に転送 SHALL する。

#### Scenario: 通常の HTTP リクエストを転送する
- **WHEN** クライアントが設定済みリスンアドレスにプレーン HTTP リクエストを送る
- **THEN** ホストはリクエストを対応する upstream に転送し、upstream からのレスポンスをクライアントに返す

#### Scenario: HTTPS を CONNECT トンネリングで中継する
- **WHEN** クライアントが `CONNECT host:port` リクエストを送る
- **THEN** ホストは TCP トンネルを確立し、クライアントと upstream の間で暗号化トラフィックを透過的に中継する
- **AND** ホストはトンネル内容を復号・変更しない

### Requirement: プラグインチェーンへのディスパッチ

ホストは各リクエスト処理時点で有効なプラグインチェーンのスナップショットを取得し、チェーンの順序で `on_request` フックを、応答取得後に逆順またはチェーン順で `on_response` フックを実行 SHALL する（順序は design.md で決定された順序に従う）。

#### Scenario: プラグインが存在しない場合は素通しする
- **WHEN** 有効なプラグインチェーンが空のときにリクエストが到達する
- **THEN** ホストはリクエストをそのまま upstream に転送し、レスポンスもそのまま返す

#### Scenario: プラグインがリクエストを加工する
- **WHEN** チェーン内のプラグインが `on_request` でヘッダを書き換える
- **THEN** ホストは書き換え後のリクエストを upstream に送信する

#### Scenario: プラグインがレスポンスを加工する
- **WHEN** チェーン内のプラグインが `on_response` でヘッダを書き換える
- **THEN** クライアントは書き換え後のヘッダを受け取る

### Requirement: プラグインによる短絡応答

プラグインは `on_request` フックの結果として「短絡応答」を返すことができ、ホストはその場合 upstream に転送せずにプラグインが指定した応答をクライアントに返 SHALL す。

#### Scenario: プラグインが 403 を返す
- **WHEN** プラグインが `on_request` で短絡応答として HTTP 403 を指示する
- **THEN** ホストは upstream に接続せず、クライアントに 403 を返す
- **AND** チェーン内のそれ以降のプラグインの `on_request` は実行されない

### Requirement: プラグイン実行失敗時のフェイルセーフ動作

個々のプラグイン実行で WASM 実行エラーやタイムアウトが発生した場合、ホストは当該プラグインをそのリクエスト処理から除外し、他のプラグインとリクエスト本体の処理を継続 SHALL する（ホストはクラッシュしない）。

#### Scenario: 1 つのプラグインがパニックしてもホストは落ちない
- **WHEN** チェーン内の 1 つのプラグインがフック実行中に WASM トラップを起こす
- **THEN** ホストはエラーをログに記録し、残りのチェーンを実行してリクエスト処理を完遂する

### Requirement: CGO 非依存ビルド

ホストバイナリは `CGO_ENABLED=0` でビルド可能 SHALL であり、ビルド成果物は CGO を要する外部ライブラリに依存しない。

#### Scenario: CGO を無効にしてビルドする
- **WHEN** `CGO_ENABLED=0 go build ./cmd/...` を実行する
- **THEN** ビルドは成功する
